# 03.11 — transit-vd-import

- „Стока на път", етап 1 от 4 (решенията — `claude/stoka-na-pat-reshenia-2026-11.md` в Проекта на чата): импортът иска два файла от SAP — „Стока на път" (досегашният 18-колонен формат, посоката без промяна) и „ВД и ИД"; разпознаване по header-а, сдвояване по Документ за покупка + Материал. Ред без ВД не влиза (всички посоки), ред само във файл 2 — също. Количеството на реда е „К-во по доставка" (`delivery_qty`); `position` остава позицията в поръчката, `delivery_position` е тази в доставката. ИД (`outbound_delivery`) без водещите нули; търсенето го намира и с нулите.
- Повторен импорт: upsert по (ВД, позиция в доставката) — съществуващ ред пази status / comment / reviewed_* / transfer_date и излиза от архива; нов — `pending`; липсващо ВД → `archived_at` (PATCH, ПОСЛЕДЕН и само ако всички партиди са минали; иначе червен toast). Ръчните редове (без ВД) импортът не пипа. „🗑 Изчисти всички" + `confirmClearTransit()` махнати (и въпросът „да изчистя ли" след износа). Чип „🗄 Архив" (винаги, и при 0) — само за четене, без бутони. Excel: ВД, ИД, К-во по ВД. transit.js — функции 45 → 56.
- Архивът е изключен навсякъде: bulletin.js, report.js + send-scheduled-report v65, minusi.js, checklist.js, loading.js (2 места). База: `transit-vd-schema.sql` (+ `-down.sql`) — 5 колони, уникален индекс БЕЗ where (PostgREST on_conflict не насочва частичен), `archived_at is null` в `transit_store_done_since`, `transit_mark_empty_stores`, `checklist_portal_values` (старите тела сверени с md5 срещу базата). Миграция **20261103122006** `transit_vd_import` (apply_migration, 03.11.2026) — в базата сверени колоните (5 + imported_at), индексът `goods_transit_vd_pos_uniq` и md5 на трите функции (15dca3ac… / c2b3ca25… / 58c36965…, = генерираните), правата непроменени; файловете `supabase/migrations/20261103122006_transit_vd_import(_down).sql`.
