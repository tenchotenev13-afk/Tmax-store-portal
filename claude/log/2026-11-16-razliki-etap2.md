# 16.11 — razliki-etap2

Етап 2 по срещата за таб Разлики (12.11.2026) + уточнение на Тенчо 16.11: решените редове не са за магазина, а за офиса. Само `stock-differences.js` + тестове, без схема → без ред за Живко.

- **Правило.** Обектът (групата на етап 1 — `sdStoreRowsView()`: `sdStoreHintsOn()` + роля manager / sklad / info; kasa / user на обект не са в нея) вижда в „Решени редове“ САМО редовете, по които трябва да действа: тип „Заприхождаване“ / „Връщане“, неотбелязан, неприключен, не 'received' (`sdStoreMustAct` → `sdRowAwaitsMark`). Същата `sdRowAwaitsMark` решава и бутона „📥 Заприходена“ / „✅ Върната“ — двете не могат да се разминат. Филтърът е в `sdTableRows`, затова превключвателят „Решени редове (N)“, чиповете по тип и Excel броят само тези редове — **броячите, оставени от етап 1, се решават с този етап.** Печатът е по бланка и не минава оттук.
- **Чиповете по статус** („Всички / Чакащи / Приключени“ и „📝 Чакат моя отговор“) при обекта не се рисуват — **нарочно скрит контрол по решение, правило 11 не важи.** Остава само 📥 Excel. Запомнен `sdFilter` пада на 'all' ПРЕДИ `sdTableRows`. „Чакат моя отговор“ брои междускладови редове, а в живата база междускладов ред с тип няма (16.11.2026: 0 от 1688) → в „Решени редове“ при обекта винаги 0. Филтърът „Само чакащите мен“ над „Бланки за преглед“ — непроменен.
- При 0 реда — „Нищо не чака вас тук“ вместо „Няма записи.“; превключвателят остава.
- **Единствената промяна, която засяга офиса:** бутонът за отметка вече ползва `sdIsTaken` (и 'capitalized'), не само `status==='taken'`. В базата има 1 ред writein/capitalized — на него офисът вече не вижда излишния „📥 Заприходена“. Решение на Тенчо 16.11: остава.
- Не са пипани: баджът на таба (`sdUnreviewedCountFor`), надписът в Бюлетина, `report.js`, отметката „РАЗЛИКИ ЛОГИСТИЧНИ СКЛАДОВЕ“ — не четат `sdTableRows`. Регионалните (`is_regional`) са 6 профила accounting/admin в ЦО → `isGlobal()`, правилото не ги засяга.
