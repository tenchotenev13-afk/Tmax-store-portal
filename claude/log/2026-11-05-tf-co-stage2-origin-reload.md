# 05.11 — tf-co-stage2-origin-reload

- Трансфери, етап 2 по идеята на Хасан Шатов (решение на Тенчо 05.11 — без нов бутон): началният обект вижда „➕ Дотовари" на свой транспорт, докато той не е тръгнал — без `departed_at`, без нито една отметка по товарите, не е Завършен (`tfOriginCanReload`); важи и за куриер преди първото „Предаден". Спирките, „Тръгна", `tfCoAutoSent`, `tfCanDelete` — без промяна.
- Формата: „➕ Добави товар — <№>", маршрутът е целият (`at = -1`), „before" — само началото; валидацията пуска куриер само за началото. `loaded_at_store = null` за товар от началото — изпращачът остава `from_store` (`tfCargoSender`), без „дотоварен в" в картата / печата / търсенето; извън transfers.js полето само се чете (notifications.js).
- `tfSubmitReload` за началото: свежо четене `transfers?select=…,transfer_cargo_events(id)` (една заявка — `sbGet` при грешка връща [] и отделна заявка не различава „няма отметки" от „паднала") → тръгнал / с отметка / непрочетено → червен toast, 0 POST.
- Без схема → без rollback SQL и без ред за Живко. Функции в transfers.js 173 → 174.
- Тест: `tests/tf-co-stage2-origin-reload.test.js` (39 проверки, истински клик, вкл. „Тръгна" след добавянето → КЗ sent); мутанти M1–M4 падат.
