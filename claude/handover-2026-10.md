## 3. Как работим (правила, които не са в CLAUDE.md)

- Този чат (архитектура/надзор) не пише код в проекта — дава **TASK блок**
  за Claude Code в отделен code block, самодостатъчен, с едно име на целева
  сесия, без „ако…“ алтернативи. Обяснението за Тенчо е преди блока.
- Claude Code: синхронизира с origin/main, пише с LF, `node --check`, jsdom
  тестове с реален клик + мутационна проверка, `npm test`, **не комитва и не
  деплойва без „давай“**. Комит — само поименни файлове, никога `-A`.
- Всеки отчет от Claude Code завършва със секция „Какво не е проверено /
  какво остава“. „Готово“ = живият файл съвпада с комита + проверено с реални
  данни + минати и двата пътя (обект и ЦО) + ясно кой получава кое известие.
- Многостъпкова задача: в началото общ брой стъпки и кои са минимумът; след
  всяка стъпка един ред статус; при „докъде сме“ — таблица по стъпки.
- Тенчо тества на живо сам и докладва. Често държи няколко Claude Code
  сесии паралелно — `git fetch` непосредствено преди комит.
- Отделни резултати (имейл до колега, списък за одобрение) — като отделен файл.
- Инструкции за потребители: skill `temax-instrukcia` (PDF + Word, реални
  снимки). Контекстен пакет за нова сесия: `npm run brief`.

## 4. Технически поуки (кратко; подробно в technical-learnings и CLAUDE.md)

- `today()` в shared.js е местна от bd898ea (13.09) — `localDateISO()`, заковано
  в `tests/local-date.test.js`; до тогава беше UTC.
- Байтова проверка на комит: `git cat-file blob HEAD:файл`, не `git show`.
  CR проверка: `| grep -c $'\r$'` трябва 0 (и grep връща код 1 при 0 — не го
  вериги с `&&`).
- Сравнение с живия сайт: `raw.githubusercontent.com/.../<пълен SHA>/файл`,
  никога branch URL (CDN кеш ~5 мин).
- Edge функциите, деплойнати от Dashboard, идват с CRLF — `tr -d '\r'` преди cmp.
- PostgREST реже на 1000 реда — страниране (образец `checklistGetAll`).
- `kasa_storno`: ~20% от редовете са въведени в друга седмица от `storno_date`
  — седмични прозорци по `storno_date`, не по `created_at`.
- Кирилица в имейли: base64 тяло + `encodeSubject()` за темата.
- A4 при `@page margin:10mm` = 190 mm полезна ширина; глобалните CSS правила
  в index.html (`th{white-space:nowrap}` и др.) бият print стиловете.
- RLS: ~25 таблици са без RLS с публичен anon ключ — известно, НЕ се
  „оправя“ с `using(true)`; истинската поправка е през edge функции със
  service ключ (направено за `users` на 30.09: anon е само за четене, без
  хешове; записите минават през `admin-users`, `auth-login`,
  `auth-set-password`, `set-history-pin`).
- Миграциите в `supabase/migrations/` са архив, не огледало — timestamp-ите
  не съвпадат с приложените; решено да остане така.

## 7. Бизнес факти, които лесно се губят

- 18 отчитащи се обекта (`users`), 23 в `stores` — разминаване в проценти.
  7 регионални (`is_regional=true`); двата склада са в `assigned_stores` на

- Складовете работят на телефон/таблет на рампата; SAP не експортира
  стоковата разписка; стоката върви в кашони със SAP код, име, брой.
- Междускладови разлики: повредена стока → сигнал, но се приема и после се
  бракува; излишък се приема с знанието на склада и контролинга;
  фиктивните SAP движения може да ги пусне всяка страна.
- Сторно с нова сума под върнатата не отговаря на изискванията (причина за
