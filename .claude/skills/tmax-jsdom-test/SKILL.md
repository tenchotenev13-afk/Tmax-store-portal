# jsdom тестове за Tmax-store-portal

Порталът е vanilla ES5 в global scope, с inline `onclick="..."` атрибути и
string-concat HTML. Това означава две неща:

1. **Прегледът на кода не хваща счупени бутони.** Апостроф в име на клиент,
   липсваща глобална функция или грешно избягана кавичка изглеждат наред при
   четене и гърмят при клик. Единственият надежден начин е да се изпълни
   реалният onclick.
2. **Файловете зависят един от друг през глобалния scope.** `history.js` ползва
   storno helper-и от `kasa.js`; `notifications.js` обвива `startApp` от
   `shared.js`. Тестване на един файл поотделно пропуска точно тези счупвания.

Този skill дава готов harness, за да не се пише boot код наново всеки път.

## Кога

- Преди да предложиш променен JS файл за commit — задължително.
- Когато промяната пипа повече от един файл (споделени глобални функции).
- Когато потребителят каже "не работи" и вече си проверил, че живият файл е
  актуален.

## Как

### Стъпка 1 — бърза проверка на зареждането

```bash
node .claude/skills/tmax-jsdom-test/smoke.js .
```

Зарежда всичките 22 файла ЗАЕДНО, в реда от `index.html`, и докладва:

- файл, който гърми при зареждане,
- име, предефинирано от по-късен файл (нова колизия).

Тече за секунди. Exit code 0 = чисто. Известните и нарочни случаи (`fmtMoney`,
веригата обвивки около `startApp` и `renderMetrics`) са в `KNOWN_COLLISIONS` в
`smoke.js` — ако изскочи ново име, преценѝ дали е нарочно обвиване (вика
оригинала) или тиха подмяна.

### Стъпка 2 — функционален тест

Копирай `example.test.js` като `tests/<фийчър>.test.js` и пренапиши
секциите. Не забравяй да оправиш пътя на require — тестът живее в `tests/`,
затова е с `../`:

```js
const H = require('../.claude/skills/tmax-jsdom-test/harness');
```

Добави името на новия файл в списъка `TESTS` в `tests/run-all.js` (ред 16).
Списъкът е изричен — папката НЕ се сканира, така че нерегистриран тест
никога не се пуска и мълчи, вместо да пада.

Пускане:

```bash
npm test                        # целият пакет през tests/run-all.js
node tests/<фийчър>.test.js .   # само този тест
```

Exit code 1 при поне една паднала проверка. `run-all.js` спира при първия
провал и не пуска останалите.

## API на harness.js

### `boot(opts) → { w, doc, calls, setData, close }`

```js
const h = boot({
  modules: ['transport.js', 'client-orders.js'],  // shared.js се добавя сам
  user:    { email:'sn@temax.bg', role:'supply', store_name:'Централен офис' },
  data:    { client_orders: ORDERS, transport_orders: [] },
  fail:    { POST: /transport_orders/ },          // симулира провалена заявка (виж долу)
  confirm: true,                                  // отговорът на window.confirm
  globals: { someGlobal: 42 }                     // задават се СЛЕД зареждането
});
```

- `modules` се подреждат автоматично по реда от `index.html`. Файл извън
  `MODULE_ORDER` хвърля грешка — добави го на правилното място в `harness.js`.
- **Слагай и модулите, които редактираният файл ВИКА.** Пример: `client-orders.js`
  вика `updateBadges()` от `notifications.js` след PATCH. Без него тестът пак
  минава, но в конзолата тихо стои `ReferenceError` — а в браузъра баджовете не
  се обновяват. Ако видиш `X is not defined` в изхода, `grep -l "function X" *.js`
  и добави файла.
- `data` е рутиране по име на таблица от Supabase URL-а (`/rest/v1/<table>`).
  Стойността може да е масив или `fn(url)`.
- `fail` приема правило за всеки метод (`GET`, `POST`, `PATCH`, `DELETE`):

  | Правило | Значение |
  |---|---|
  | `true` | всяка заявка с този метод пада — 500, тяло `{message:'boom'}` |
  | `/regex/` | падат само URL-ите, които съвпадат (същият 500) |
  | `fn(url)` | пада при истина; може да върне и обект-спецификация |
  | `{ status, body, url }` | точен контрол |

  В обектната форма: `status` е HTTP кодът (по подразбиране 500), `url` по
  избор стеснява кои заявки падат (`/regex/` или `fn`), а `body` е тялото на
  отговора. **Липсващо `body`, `null` или `''` значи ПРАЗНО тяло — тогава
  `json()` хвърля `SyntaxError`, точно както прави браузърът.**

  ```js
  fail: { GET: { status: 401, body: { message: 'Invalid API key' } } }
  fail: { GET: { status: 401 } }                       // празно тяло → json() хвърля
  fail: { GET: { status: 404, url: /stores/ } }        // пада само заявката към stores
  ```

  Празното тяло не е екзотика — точно това връща Supabase при 401 без
  `apikey` хедър, и точно този случай `sbGet` вече поема, без да хвърля.
  Мрежов срив (`fetch` отхвърля, преди да има отговор) НЕ се симулира през
  `fail` — подмени `w.fetch` директно в теста.
- `calls` събира заявките и страничните ефекти. **Формите се различават —
  не всяко поле е обект:**
  - `get` — масив от **URL низове** (не обекти). `calls.get[0]` е самият
    URL; `calls.get[0].url` е `undefined` и тестът минава мълчаливо.
  - `del` — също масив от **URL низове**.
  - `post`, `patch` — масив от `{url, table, body}`, където `body` е вече
    парснатият JSON от заявката.
  - `notOk` — `{method, url, status}` за всяка заявка, върнала `ok:false`.
    Основното оръжие срещу тихо погълнатите грешки.
  - `toast`, `confirm`, `alert` — съобщенията, подадени към всяко от тях.
  - `scrollTo` — двойки `[x, y]`; `scrollIntoView` — `{id, opt}`.

Модулните файлове държат данните си в глобални масиви (`clientOrders`,
`transportOrders`, …). `boot()` НЕ ги пълни — попълни ги сам след boot, както
истинският `load*()` би направил след `sbGet`, включително изчислените полета
(`_status`, `_days`, `_isFulfiller`). Виж `env()` в `example.test.js`.

### Кликове

```js
realClick(w, el)          // изпълнява onclick с правилен `this` — истински клик
tryClick(w, el)           // същото, но връща грешката вместо да хвърли
fire(w, el, 'change')     // onchange / oninput / onsubmit
```

### Търсене на елементи

```js
btn(root, 'Изпратена')      // САМО <button>, съдържа текста
btnExact(root, 'Откажи')    // САМО <button>, точно съвпадение след trim
ctrl(root, '👥')            // button ИЛИ span/a (кликаеми баджове)
allBtns(root, 'Изтрий')     // всички съвпадения — за проверка на брой
```

**Не търси по контейнер.** Обвиващият `<div>` съдържа текста на всеки бутон в
реда, така че `div.textContent.indexOf('X') >= 0` е винаги истина и тестът лъже.
Затова помощниците гледат само `button`/`span`. Когато проверяваш че бутон
ЛИПСВА, ползвай `btn()` (само button) — статусният бадж може да съдържа същия
текст като `<span>`.

### Проверки

```js
ok(name, cond, extra)        // една проверка; връща true/false
guard(name, () => ...)       // изпълнява и се проваля, ако хвърли — вместо да убие теста
section('1. Заглавие')
report()                     // резюме + process.exit(fail ? 1 : 0)
```

`guard()` е важен: един `ReferenceError` в един рендер иначе отнася всички
следващи секции и не научаваш нищо за останалите.

`guard()` връща **true/false** (хвърли ли), не стойността на функцията — почти
всички рендери в проекта не връщат нищо. Затова се ползва така:

```js
if (guard('renderX() не хвърля', () => w.renderX())) {
  ...проверките, които имат смисъл само ако рендерът е минал...
}
```

`ok()` също връща `true/false` — удобно за същото гнездене:

```js
const row = doc.getElementById('co-row-o-1');
if (ok('редът съществува', !!row)) {
  ok('показва номера', row.textContent.indexOf('9001') >= 0);
}
```

Внимавай с този модел: прескочените проверки НЕ се броят като паднали. Ако
броят проверки в изхода намалее без причина, някое `if` мълчи.

### Дати

```js
dayOffset(-3)   // 'YYYY-MM-DD', 3 дни назад
tsOffset(-3)    // ISO timestamp
```

Ползвай ги вместо фиксирани дати, за да не гният тестовете. Локални getter-и,
не `toISOString()` за датите — България е UTC+2/+3 и `toISOString()` дава грешен
ден вечер.


## Технически бележки

- `runScripts: 'outside-only'`, файловете се зареждат ръчно с `w.eval()`.
  **Не** `'dangerously'` — при него jsdom тръгва да дърпа истинския OneSignal
  CDN скрипт от `index.html`.
- `w.eval()`, не Node `eval` — функциите трябва да са на `window`, за да ги
  вижда inline `onclick`.
- `shared.js` пуска `setInterval` за `refreshToday`. Затова тестът винаги
  завършва с `report()` (който вика `process.exit`), иначе процесът виси.
- `jsdom` вече е в `package.json` на репото; ако липсва: `npm i -D jsdom`.
